# 与bot刷抖音 · AstrBot 插件版

## 0.5.0：群聊与跨平台接续聊天

设置页采用黑白配色，分为“会话接入”“上下文与记忆”“视频与缓存”。

### 群聊接入

**群聊功能仍在测试中。目前仅完成小规模群聊验证，尚未在大群聊天中测试，稳定性未知。**

暂停回复，在专用窗口打开目标群（也可从会话列表选择），点击“绑定当前会话”，然后开启回复。群与私聊使用独立白名单；绑定只记录已有历史，不补回旧消息。当前同时监听一个明确选中并绑定的会话，不轮巡所有聊天。

默认“仅@机器人”；填写机器人在群内显示的昵称，用逗号分隔多个名称。需要响应全部新消息时选择“所有新消息”。群成员分别识别，连续消息按发送者分别处理。AstrBot 若启用入口白名单，请加入设置页显示的 `mimi-douyin:GroupMessage:...` 标识。

### 选择已有对话，调整上下文

先绑定抖音会话，再到“上下文与记忆”选择已有 QQ 或其他 AstrBot 对话并关联。近期上下文不依赖其他记忆插件，可双向接续聊天；原始记录各自保留，不覆盖、不搬动、不删除。

共享开关、消息条数、会话活跃时限、每条字数和总字数均可调整，保存后下一次回复生效。默认每渠道 8 条、会话 48 小时内有更新、每条 600 字、合计 12000 字；活跃时限设为 0 表示不限。近期上下文的开关与活跃时限不限制长期记忆检索；记忆摘录仍受单条和总字数预算约束，不删除已有记忆。

关联指向所选具体对话。目标平台切换到另一条对话时，不会把双向关联注入未选择的对话。

### 长期记忆依赖 LivingMemory 插件

**[LivingMemory](https://github.com/lxfight-s-Astrbot-Plugins/astrbot_plugin_livingmemory) 是可选的长期记忆插件。不安装它，普通聊天、视频转述和近期上下文关联仍可用；共享或检索长期记忆时，需要安装并启用 LivingMemory，并配置其检索依赖。**

私聊可勾选“参考长期记忆”，两边按同一主私聊范围保存与检索；同人格过滤仍由 LivingMemory 控制。已有 LivingMemory 私聊关联可继续使用，近期上下文范围受本页设置控制。解除关联保留已有历史和记忆，不搬迁旧数据。

私聊的双向记忆共用需要 LivingMemory 版本提供 `access_control.shared_private_sessions` 设置；缺少该能力时页面会明确提示，不会改动原记忆库。群聊只读检索需要其记忆检索引擎可用。

“群聊读取所选 QQ 对话与记忆”默认关闭。管理员开启后，还需明确选择要参考的 QQ 私聊或 QQ 群对话。个人私聊只向群聊单向、只读提供参考；群内新发言仍属于群成员，不写成该 QQ 用户的个人经历。长期记忆检索同样依赖 LivingMemory。

让机器人在抖音私信里聊天，实际读取你分享的视频、图文和作品简介。可以单独运行，也可以装进 AstrBot。

## 能做什么

- 回复当前绑定的抖音私信，支持白名单。
- 读取分享视频的完整画面，单独提取音轨核对对白。
- 按顺序读取图文里的原图，避免只看封面就说自己读完了。
- 把作品简介、画面字幕、声音分别提供给聊天模型。
- 让机器人自己刷推荐作品，也可以读完再找你聊天。
- 开启评论开关后，在实际读过的作品下留言。只有拿到服务器返回的评论 ID，才算发出；结果不明确时不自动重发。

目前发送文字消息。图片和视频会先保存到本机，再交给你配置的模型处理。

## 先准备这些

| 需要什么 | 用来做什么 | 怎么准备 |
| --- | --- | --- |
| Python | 运行独立版 | 从 [Python 官网](https://www.python.org/downloads/)安装受支持的版本。本机验证用的是 Python 3.12。 |
| Node.js 和 npm | 连接浏览器 | 从 [Node.js 官网](https://nodejs.org/en/download)选择 LTS 版本。程序最低要求 Node.js 20。 |
| Edge 或 Chrome | 登录抖音、读取页面 | 已经装了就直接用；也可以在设置页下载单独的 Chromium。 |
| FFmpeg 和 FFprobe | 检查视频、压缩文件、提取音轨 | 从 [FFmpeg 下载页](https://ffmpeg.org/download.html)选择自己系统的安装包。Windows 下载可运行的构建包，不要下载源码包。 |
| 模型接口 | 聊天、看视频和图文 | 准备接口地址、密钥、聊天模型名、视频模型名。它们不包含在发布包里。 |
| 机器人抖音账号 | 接收和回复私信 | 首次使用需要自己登录。 |

Windows 可以把程序放到 `D:\Tools\DouyinBot`。Python、Node 和 FFmpeg 也可以装在 D 盘，不要求使用某个固定位置。

FFmpeg 安装包里应同时有 `ffmpeg.exe` 和 `ffprobe.exe`。把它们所在目录加入 PATH，或者在设置页手动填写程序路径。只聊文字时不需要这两个程序；看视频和核对声音时需要。

## 独立运行：Windows

1. 把独立版压缩包解压到一个固定目录，例如 `D:\Tools\DouyinBot`。
2. 安装上面列出的 Python 和 Node.js。安装 Python 时保留 Python 启动器，确保命令行能用 `py`。
3. 双击 `setup.bat`，等依赖安装完成。首次安装会联网下载 Python 依赖，在当前目录创建自己的 `.venv`。
4. 双击 `start.bat`。这个窗口要保持运行，关掉后程序就停止了。
5. 用浏览器打开终端显示的地址，默认是 `http://127.0.0.1:8787`。

`setup.bat` 只在首次安装或更新依赖时运行。平时双击 `start.bat` 即可。

如果你习惯用命令行，也可以在解压目录运行：

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r standalone-requirements.txt
.\.venv\Scripts\python.exe -m mimi_douyin serve --data-dir .\data
```

## 独立运行：Linux 或 macOS

在项目目录运行：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r standalone-requirements.txt
.venv/bin/python -m mimi_douyin serve --data-dir ./data
```

浏览器首次登录需要图形桌面。纯命令行服务器或 Docker 不能直接扫码，需要先准备桌面、VNC 或 X11；Linux 的 Chromium 还可能需要系统库，按 [Playwright 官方说明](https://playwright.dev/docs/browsers)安装。程序不会自动执行提权安装。

目前实际验证以 Windows 为主，Linux 和 macOS 的账号登录仍需自行检查。

## 第一次打开设置页，按这个顺序来

### 1. 填模型接口

填好聊天接口地址、密钥和模型名称，地址通常是服务商提供的、以 `/v1` 结尾的接口根地址，不是网页地址，也不是完整的 `/chat/completions` 地址。

再填看视频和图文的模型名称。它可以和聊天模型不同。视频如果用另一家接口，就展开“视频使用另一家接口”，单独填地址和密钥；使用同一份密钥时，勾选对应选项。

点击“保存设置”，再点“测试聊天接口”。测试成功只说明聊天接口能连通，不代表所选视频模型一定能接收视频。

密钥保存后不会回显。密钥框留空会保留已有值，换密钥时直接填新的。

### 2. 选择保存目录，检查依赖

点击“选择文件夹”，选视频和图文要保存的位置，再保存设置。选的是运行程序的电脑上的目录，不是访问设置页的手机本地目录。

留空时使用数据目录里的 `media`。更换目录只影响新文件，已有视频和登录资料不会搬动或删除。想新建目录，也可以直接输入完整路径后保存。

查看依赖表：

- Node、FFmpeg、FFprobe、浏览器会自动查找。
- 缺 Playwright 时，点击“安装浏览器连接组件”。这是连接浏览器的程序包，会装在本项目数据目录里。
- 已有 Edge 或 Chrome 就不必再下载浏览器。没有时再点击“下载 Chromium 浏览器”。

重新检测不会自动下载。刚装完程序却检测不到，可以重启本程序，或展开手动路径设置，直接填写程序位置。

### 3. 登录、绑定、开启回复

请按下面的顺序操作。机器人账号负责收发回复，你自己的账号负责向机器人发消息；两边不要混淆。

1. 在设置页点“打开登录窗口”。**后续登录和打开私信，都在本程序弹出的专用浏览器窗口中完成**；平时浏览器里已打开的私信不代表程序已经连接。
2. 在专用窗口登录机器人的抖音账号，完成可能出现的验证码或安全验证。
3. 点击抖音的“消息”，再点开要回复的那位用户，直到能看见聊天记录和输入框。只停在首页或消息列表，还不能读取目标私信。
4. 确认这个会话里有双方发出的消息。如果机器人账号从未发过消息，先在专用窗口手动回一条普通文字，便于程序确认收发方向。
5. 回到设置页点“绑定当前私信”，核对显示的对象名称，再点“开启回复”。绑定时只记录已有历史，旧消息不会补回，不要用绑定前发过的消息验证是否正常。
6. 从自己的账号向机器人发一条**新的纯文字消息**。确认能回复后，再分享视频或图文。

第一次绑定会把当前对象加入白名单。白名单开启但为空时，所有人都不能触发回复。

“浏览器已打开”“已绑定”“回复开关已开启”和“正在监听新私信”是不同阶段。需要查看最新状态时，独立版点右上角“刷新状态”，AstrBot 版点“重新检测”。显示“正在处理消息”时，视频和图文正在下载、识别或生成回复，通常比纯文字慢；请等待，不要反复绑定或重开窗口。

读取分享内容时，可能临时打开作品标签页，正常结束后会关闭这个临时页。请保留原来的私信页；看到作品页不代表私信接入已经断开，也不需要不断手动切回私信。

### 关闭窗口后继续使用

- **只关了私信面板**：在专用窗口重新点击“消息”，进入已绑定的目标会话，回设置页刷新状态；回复已暂停时再点“开启回复”。同一对象不必重复绑定。
- **整个专用浏览器窗口都关了**：回设置页点“重开登录窗口”。程序会尝试恢复已绑定会话；没有恢复时，手动点击“消息”并进入目标私信，确认对象后再开启回复。浏览器弹出不代表私信已经就绪，不要依赖关闭窗口后自动重新弹出。
- **换机器人账号或私信对象**：先“暂停回复”，在专用窗口登录并打开新的目标会话，再绑定、核对白名单，最后“开启回复”。

平时保持专用窗口里的目标私信打开即可，不必一直置顶。设置页也可以关掉，重新打开时无需重新绑定。

### 4. 想让她自己刷，再开自主活动

勾选“允许机器人主动聊天或自己刷抖音”，设置活动间隔后保存。也可以点击“实际读一条推荐作品”先试一次。

定时触发后，她可以选择找你聊天、自己读一条作品，或者读完再聊。只有真正取得媒体内容并完成转述，才会登记为读过。

公开评论是单独的开关，默认关闭。不打开评论开关，仍然可以看作品和私聊。打开后，她只能评论本程序实际读取过的作品。

## 如果你使用 AstrBot

安装插件版压缩包，打开 **与bot刷抖音 → 接入设置**，选择目录、检查依赖、登录和绑定即可，不需要再启动独立版。

聊天和视频模型在 AstrBot 的模型提供商里配置，再到插件设置里选择。聊天模型和人格留空时沿用当前 AstrBot 配置，插件不会改写人格正文。

如果 AstrBot 还开着入口白名单，把接入设置页显示的抖音会话 ID 加进去，或为 `mimi-douyin:FriendMessage:*` 分配独立配置。

“允许机器人自己刷抖音”会提供实际观看工具。有本项目配套的主动回复插件时，这些工具会加入原来的主动回复任务，不另外增加定时器。模型也可以在已绑定的私信中按要求使用。

如果你维护的是已有的配套主动回复插件，接入补丁单独打包，说明见 [主动回复接入](integrations/README.md)。独立版不需要这个补丁，也不需要另装主动回复插件。

管理员有 QQ 时，也可用 `/抖音 登录`、`/抖音 状态`、`/抖音 查看`、`/抖音 绑定`、`/抖音 开始`、`/抖音 暂停`。没有 QQ 也能直接用设置页。

## 聊天记录和记忆放在哪里

独立版默认把数据保存在启动时指定的 `data` 目录：

- `config.json`：模型和程序设置，含密钥，不要上传或分享。
- `messages.db`：聊天历史、观看记录和发送状态。
- `media`：实际下载的视频、图片和提取的音轨。
- `browser-profile`：浏览器登录资料，不要打进发布包。
- `runtime`：安装的 Playwright、可选 Chromium 和安装日志。

独立版更换聊天风格后使用另一组历史范围，旧记录仍保留。它不会自动读取或迁移 AstrBot 的人格、QQ 聊天和长期记忆。

图文只依据实际下载的图片和已取得的声音说明内容。没有取得图文配乐时，会明确说明未提供音频。

AstrBot 版的数据仍由 AstrBot 管理。“记住看过的视频”和长期记忆关联需要配套 LivingMemory 支持；普通聊天、媒体转述和近期上下文关联不依赖它。开启“延后视频向量入库”时先在本地保存摘要，恢复向量服务后可补存，不重复调用视频模型。

## 常见问题

**必须一直把私信放前台吗？**

不用一直放前台，但专用窗口里的目标私信要保持打开。启动时会尝试恢复绑定会话；页面关闭、登录失效或恢复失败时，需要手动处理。当前版本不会轮巡所有私信。

**浏览器为什么会弹到前面？**

可见浏览器的自动操作可能抢焦点。程序已减少回复时的鼠标操作，读取作品使用后台标签页；实际效果仍受浏览器和网页影响。首次登录会显示窗口。无头模式可能触发抖音验证码，不适合直接当作默认解决办法。

**看起来登录了，却一直读不到消息？**

先确认打开的是本程序的专用窗口，并且登录的是机器人账号；再点击“消息”进入目标会话，看到聊天记录和输入框。确认绑定对象、白名单和回复开关后，用自己的账号发送一条新消息。若停在验证码或安全验证页面，需要手动完成验证。

若显示“正在处理消息”，请先等待分享内容下载、识别和回复生成。刷新状态可以查看进度，不要在处理中重复绑定或重开窗口。处理失败时按页面给出的错误提示处理，不要把“回复开关已开启”当作已完成连接。

**只读出了标题，或者说视频转述失败？**

先确认视频模型和接口真的支持媒体输入。只有封面或标题不算读取视频；图文取不到原图、视频没有画面轨道或文件不完整时，程序会报告失败，不会编造内容。

感知接口调用失败时，会在本次超时限额内再试一次；参数或鉴权错误不重试。识别成功后会缓存转述，同一作品再次分享时可直接复用。回复发送和评论提交结果未知时，仍不会自动重发。

**浏览器静音会影响识别声音吗？**

不会。声音从实际下载的文件提取，不录制电脑正在播放的声音。

**为什么评论没有发出去？**

检查评论开关、作品是否已实际读取，以及抖音是否要求验证。页面控件识别不明确时会停止提交。没有收到评论 ID 的结果会记为失败或未知，不能当作已发出，也不会自动重发。

**怎么停止？**

先在设置页暂停回复。独立版在启动窗口按 `Ctrl+C` 停止；下次运行 `start.bat` 再打开设置页即可。

## 自己接模型接口或发布源码时

视频和聊天都使用兼容的聊天请求接口。视频感知还需要接口接收 `video_url`，图文使用 `image_url`，独立音轨使用 `file.file_data` 音频文件内容块。模型名称里有 Gemini，并不代表服务商一定开放了这些输入。只提供文字或图片输入的接口，不能替代完整的视频接口。

源码可用 `python -m pip install .` 安装，命令行入口为 `mimi-douyin`。核心包是 `mimi_douyin`，可以不安装 AstrBot；根目录的 AstrBot 入口只是可选适配。需要检查本机依赖时可运行 `python -m mimi_douyin check --data-dir ./data`。

发布时只打包源码、静态页面、依赖说明和示例配置，不带 `data`、`.venv`、`node_modules`、密钥、聊天库或登录资料。浏览器选择器参考来源和第三方许可见 [ATTRIBUTIONS.md](ATTRIBUTIONS.md)。

## 下载与缓存设置

“单条视频时长上限（秒）”默认 180 秒（3 分钟），可在接入设置随时修改，0 表示不限时长。程序在下载文件前读取播放器时长；超过上限，或开启限制时无法确认时长，会跳过下载并返回明确的未观看状态，提醒机器人换一个视频。自主推荐会避开同一上限下已跳过的作品；改变上限后可重新选择。私信分享与自主浏览使用同一限制，图文原图不受视频时长限制。保存后立即用于新下载，不必重新登录。

在 WebUI 中调整“单条作品下载上限（MB）”。它控制一条作品原视频或全部原图的总下载大小，默认 64 MB；遇到媒体总大小超限时可以调大。保存后立即用于新下载，不用重开登录窗口。送入模型的文件大小仍按模型设置压缩，两者独立。

“定时清理媒体缓存”默认关闭。开启后可设置每隔多少小时清理、保留最近多少小时的缓存；保留时长填 0 表示清理全部已经用完的媒体。程序启动后重新计时，关闭期间不运行；开关、间隔和保留时长会保存。下载、识别和相关任务进行时会推迟清理。

只处理当前缓存目录中本程序管理的媒体文件及其压缩、音轨副本，聊天记录、观看转述和登录资料保留。自选目录里的未登记文件会保留；应用默认缓存目录支持识别旧版生成的文件。页面显示下次清理时间和上次释放的空间。

## 机器人名称和人格

界面中的“机器人”是通用称呼，不预设姓名、性别或与用户的关系。AstrBot 版使用你在 AstrBot 中选择的人格。更新不会替换已有的人格、聊天风格或历史记录。


### 分享卡片加载变化

收到分享时同时保存原作品链接和已有的原生消息编号。随后卡片封面或内容刷新、临时定位编号变化时，仍读取这次分享对应的原作品；不会改读另一条最近视频，也不按发布者昵称猜测。尚未拿到链接时最多重新检查 3 次；仍失败会明确提示重新分享或发送作品链接。会话对象变化时停止读取。原有视频时长、大小上限和内容识别流程继续生效。
